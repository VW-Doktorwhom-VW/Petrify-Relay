Petrify relay

Plugin 1.2.1.0 starts a bundled relay process with Jellyfin. It lets Petrify apps discover this server on the LAN, see connected Petrify devices, hand off playback and coordinate synchronized listening parties and guest voting. It also proxies Jellyfin artwork and audio requested by clients.

What it checks and handles

  • LAN discovery answers Petrify discovery packets; device connections report presence and playback state. Device counts refer to relay-connected Petrify clients, not every Jellyfin session.
  • For faster media access, the relay compares Jellyfin's public server ID at the client-supplied server address with local candidate addresses. A matching ID allows a local route; this does not change library permissions.
  • Client media requests can carry Jellyfin access tokens, and party features handle playback, queue and guest-invite data. Treat the relay as a trusted-network service, not an authenticated public administration API.
  • The optional check below requests only the relay's health endpoint. It displays its reported version, protocol, connected-device count and party on/off state, never credentials, invite links or raw responses. It does not scan your library, test UDP discovery or verify audio synchronization.

All saved settings require a Jellyfin restart. Saving does not restart the relay or change its running ports. No health requests run automatically.

In containers, localhost means the container. No passwords, API keys, queries or fragments. The relay may also try Jellyfin's advertised local address; this list is not an access-control allowlist.

Party timing

Lead times schedule playback ahead so devices can prepare. Increase cautiously for slower networks; higher values also make controls feel slower. These do not replace per-device synchronization adjustments in Petrify.

Default 1000; allowed 300–30000. Preparation time for synchronized party playback commands.
Default 2200; allowed 800–30000. Extra preparation time when a party loads a different track.
